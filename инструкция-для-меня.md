## Как устроена система

```

  ├── catalog.yml              ← описание продукта

  ├── repos.yml                ← список участников
  ├── catalog.json             ← собранные данные (генерируется автоматически)
  ├── scripts/collect.py       ← скрипт коллектора
  ├── .github/workflows/
  │   └── collect.yml          ← запускается при релизе участника или раз в день
  └── docs/
      ├── index.html           ← сайт каталога
      ├── catalog.json         ← копия для сайта (генерируется автоматически)
      └── images/              ← картинки продуктов (генерируются автоматически)

Сайт каталога: https://kbTPKsteel.github.io/TPK/
Локальный репо: C:\Users\userkmd07\source\Repos\TPK
```

## Добавить нового участника

### Что сделает участник (по инструкции для участников):
1. Создаст токен `TPK-read` (`repo` + `workflow`) и отправит мне
2. Добавит `catalog.yml`, картинку и `notify-tpk.yml` в каждый свой репо
3. Добавит секрет `TPK_DISPATCH_TOKEN` в каждый свой репо

### Что делаю я:

**1. Добавить токен участника как секрет в kbTPKsteel/TPK**
- Открыть `github.com/kbTPKsteel/TPK`
- **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
- **Name:** `TOKEN_УЧАСТНИК` (например `TOKEN_VASIA`)
- **Secret:** *(токен от участника)*
- Нажать **Add secret**

**2. Добавить участника в repos.yml и collect.yml**

Открыть `C:\Users\userkmd07\source\Repos\TPK\repos.yml`, добавить:
```yaml
  - username: имя_аккаунта_на_github
    token_secret: TOKEN_УЧАСТНИК
    display_name: Имя Фамилия          # отображается на сайте вместо ника
```

Открыть `C:\Users\userkmd07\source\Repos\TPK\.github\workflows\collect.yml`, добавить строку в секцию `env` шага "Run collector":
```yaml
          TOKEN_УЧАСТНИК: ${{ secrets.TOKEN_УЧАСТНИК }}
```

Сохранить оба файла и запушить:
```
git -C "C:\Users\userkmd07\source\Repos\TPK" add repos.yml .github/workflows/collect.yml
git -C "C:\Users\userkmd07\source\Repos\TPK" commit -m "Add contributor: имя"
git -C "C:\Users\userkmd07\source\Repos\TPK" push
```

**3. Передать участнику:**
- Значение `TPK_DISPATCH_TOKEN` — токен `TPK-dispatch` из моего главного аккаунта
- Файлы с рабочего стола: `notify-tpk.yml` и `инструкция-для-участников.md`

**4. Запустить коллектор вручную (для проверки)**
- `github.com/kbTPKsteel/TPK` → **Actions** → **Collect Releases** → **Run workflow** → **Run workflow**

## Удалить участника или продукт

**Убрать участника полностью:**
1. Удалить его строки из `repos.yml` и из `collect.yml` → запушить
2. Удалить секрет `TOKEN_УЧАСТНИК`: Settings → Secrets → найти → Delete
3. Запустить коллектор вручную — его продукты уйдут из каталога

**Убрать один конкретный продукт:**
Участник удаляет `catalog.yml` из своего репо → коллектор уберёт продукт при следующем запуске.

## Ручной запуск коллектора

Когда нужен: добавили участника, хотим проверить, что-то пошло не так.

`github.com/kbTPKsteel/TPK` → **Actions** → **Collect Releases** → **Run workflow** → **Run workflow**

Автоматически коллектор запускается:
- Когда участник публикует Release — в течение 1–2 минут
- Каждый день в 6:00 UTC — как резервный вариант

## Типы продуктов и логика файлов

Тип задаётся в `catalog.yml` участника (`type: ...`) и определяет, какие файлы из релиза попадут в каталог.

| Тип | Отображение | Логика скачивания |
|-----|-------------|-------------------|
| `app` | Приложение | Для каждой версии Tekla: сначала архив `*_TeklaXXXX.*`, иначе `*_TeklaXXXX.exe`. Если ни одна версия Tekla не найдена — релиз пропускается |
| `plugin` | Плагин | То же самое, но ищет `.dll` вместо `.exe`. Релиз без подходящих файлов пропускается |
| `macro` | Макрос | Все файлы из релиза, версия Tekla не определяется |
| `other` | Прочие инструменты | Все файлы из релиза, версия Tekla не определяется |

**Поддерживаемые форматы архивов:** `.zip`, `.7z`, `.rar`, `.gz`, `.tar`

**Имя отображаемого автора** на сайте берётся из поля `display_name` в `repos.yml`. Если поле не заполнено — показывается GitHub-ник.

## Если истёк токен TPK-dispatch

Этот токен хранится как `TPK_DISPATCH_TOKEN` у каждого участника в их репо.

1. Создать новый `TPK-dispatch` в своём главном аккаунте (галочка `workflow`)
2. Сообщить каждому участнику новое значение — они обновят секрет у себя:
   - Их репо → **Settings** → **Secrets** → `TPK_DISPATCH_TOKEN` → **Update**

---

## Если истёк токен участника (TPK-read)

1. Попросить участника создать новый токен и прислать
2. Обновить секрет в `kbTPKsteel/TPK`:
   - **Settings** → **Secrets** → `TOKEN_УЧАСТНИК` → **Update**

## Как хранятся файлы релизов

**Файлы копируются в центральный репо**, а не скачиваются напрямую из репо участника. Схема:

1. Участник публикует релиз у себя (репо может быть приватным)
2. Коллектор скачивает файлы из релиза участника
3. Создаёт тег в `kbTPKsteel/TPK` вида `{product-id}-{версия}`
4. Загружает файлы туда через `gh release upload`
5. В `catalog.json` прописывается ссылка на центральный репо

Пользователь скачивает с публичного `kbTPKsteel/TPK`, не с репо участника — поэтому репо участника может быть приватным.

**Если участник удалил релиз у себя:**
- Файлы в `kbTPKsteel/TPK` **останутся** — коллектор никогда ничего не удаляет из центрального репо
- При следующем запуске коллектора версия **исчезнет** из `catalog.json` и UI
- Прямые ссылки на файлы технически продолжат работать (файл на месте), но пользователь уже не найдёт версию через сайт

**Лимиты GitHub на релизные ассеты:**
- Один файл — максимум **2 ГБ**
- Общий объём — официально не ограничен (хранится отдельно от git-истории)
- Количество релизов — не ограничено

**Если удалены все версии продукта:**
Продукт **останется** в каталоге с пометкой "Нет версий". Он исчезнет только если участник удалит `catalog.yml` из своего репо.
