# Как оформить инструкцию в catalog.yml

Поле `instructions` в `catalog.yml` поддерживает **Markdown** — сайт сам
превращает его в отформатированный текст на вкладке "Инструкция". Ниже —
примеры того, что уже красиво отображается на сайте, чтобы инструкция не
превращалась в сплошную стену текста.

---

## Заголовки для шагов

Каждый шаг лучше оформлять отдельным заголовком (`###`), а не просто
абзацем текста — так шаги визуально разделяются.

```markdown
### Шаг 1. Выделите трубу
В Tekla Structures откройте модель и выделите нужную трубу мышью.
Окно программы должно оставаться открытым — свернуть его можно, закрывать не нужно.

### Шаг 2. Проверьте параметры в окне
Обычно ничего менять не нужно, значения по умолчанию подходят для большинства случаев.
```

Крупные разделы (например, "Установка" и "Использование") лучше оформлять
через `##`:

```markdown
## Установка
Скачайте и запустите файл из раздела версий.

## Использование
### Шаг 1. ...
### Шаг 2. ...
```

---

## Списки

Для перечислений (например, настроек или пунктов) используйте маркированный
список — он получает отступ и аккуратные отметки:

```markdown
- Поверхность — по умолчанию «наружная Ø», этого достаточно для разметки.
- Выпустить — какие файлы создавать. Отмечены DXF и PDF — обычно этого хватает.
- Каталог вывода — куда сохранятся файлы.
```

Для последовательности действий — нумерованный список:

```markdown
1. Скачайте файл из раздела версий.
2. Запустите его — откроется окно программы.
3. Выделите деталь в Tekla Structures.
```

---

## Выделение текста

```markdown
**Важно:** окно программы нельзя закрывать во время работы.
*Совет:* для одной трубы достаточно повторного нажатия кнопки.
```

`**жирный**` — для акцентов и предупреждений, `*курсив*` — для советов
и второстепенных пояснений.

---

## Имена файлов и команды

Названия файлов, расширения и т.п. лучше оборачивать в обратные кавычки —
они получают моноширинный шрифт с серым фоном:

```markdown
Файл `..._izgotovlenie.dxf` — по нему раскраивают заготовку.
```

---

## Частая ошибка: отступы

Если текст записан через `|` (literal block), у **всех** строк блока
должен быть одинаковый отступ (2 пробела). Если хотя бы одна строка
"вылезет" с меньшим отступом — весь `catalog.yml` перестанет читаться:

```yaml
# Правильно
instructions: |
  ### Шаг 1. Текст
  Продолжение текста с тем же отступом.

# Неправильно — вторая строка с меньшим отступом ломает файл
instructions: |
  ### Шаг 1. Текст
 Продолжение с одним пробелом вместо двух
```

---

## Что пока не поддерживается специальным оформлением

Сайт умеет показывать заголовки, списки, `код`, **жирный** и *курсив* текст —
для остального (цитаты `>`, таблицы, HTML-теги) специального оформления
пока нет, они либо не отобразятся как задумано, либо будут выглядеть как
обычный текст browser'а по умолчанию.
