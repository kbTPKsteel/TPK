# Инструкция для участников каталога TPK

Чтобы добавить свои разработки в общий каталог, нужно выполнить 4 шага.

---

## Шаг 1. Создать токен доступа

Токен нужен, чтобы каталог мог автоматически читать твои репозитории.

1. Зайди на **github.com** под своим аккаунтом
2. Нажми на аватар в правом верхнем углу → **Settings**
3. В левом меню прокрути вниз → **Developer settings**
4. **Personal access tokens** → **Tokens (classic)**
5. Нажми **Generate new token** → **Generate new token (classic)**
6. Заполни:
   - **Note:** `TPK-read`
   - **Expiration:** `No expiration`
   - Поставь галочки: ☑ **repo** и ☑ **workflow**
7. Нажми **Generate token**
8. Скопируй токен (он показывается только один раз!)
9. **Отправь токен Марии** — она добавит его в систему

---

## Шаг 2. Добавить секрет в каждый репозиторий

В каждый репозиторий, который хочешь опубликовать, нужно добавить один секрет.

1. Открой репозиторий на GitHub
2. Нажми вкладку **Settings** (в верхнем меню репо)
3. В левом меню → **Secrets and variables** → **Actions**
4. Нажми **New repository secret**
5. Заполни:
   - **Name:** `TPK_DISPATCH_TOKEN`
   - **Secret:** *(значение выдаст Мария)*
6. Нажми **Add secret**

---

## Шаг 3. Добавить файлы в репозиторий

В каждый репозиторий нужно добавить три вещи.

### 3.1 Файл catalog.yml

Создай файл **`catalog.yml`** в корне репозитория и заполни его:

```yaml
name: Название продукта
type: macro          # app / plugin / macro / other
description: |
  Краткое описание — что делает продукт и для кого он предназначен.
image: assets/preview.png
# video: https://youtube.com/watch?v=...   # необязательно
instructions: |
  ## Установка
  1. Скачать файл из раздела версий
  2. ...

  ## Использование
  ...
```

**Типы продуктов:**

| Тип | Значение | Описание |
|-----|----------|----------|
| `app` | Приложение | .exe, компилируется под версии Tekla |
| `plugin` | Плагин | .dll, компилируется под версии Tekla |
| `macro` | Макрос | .cs, не зависит от версии Tekla |
| `other` | Прочие инструменты | шаблоны, таблицы, утилиты — всё не связанное с Tekla |

### 3.2 Картинка (необязательно)

Если хочешь добавить картинку-превью:
1. Создай папку **`assets`** в корне репозитория
2. Положи в неё файл **`preview.png`** (или .jpg)
3. В `catalog.yml` укажи путь: `image: assets/preview.png`

### 3.3 Файл notify-tpk.yml

Создай папку **`.github/workflows/`** в корне репозитория (если её нет) и положи туда файл **`notify-tpk.yml`** с таким содержимым:

```yaml
name: Notify TPK Catalog

on:
  release:
    types: [published]

jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger TPK collector
        run: |
          curl -X POST \
            -H "Authorization: token ${{ secrets.TPK_DISPATCH_TOKEN }}" \
            -H "Accept: application/vnd.github+json" \
            https://api.github.com/repos/kbTPKsteel/TPK/actions/workflows/collect.yml/dispatches \
            -d '{"ref":"main"}'
```

### Итоговая структура репозитория

```
твой-репо/
├── catalog.yml                        ← описание продукта
├── assets/
│   └── preview.png                    ← картинка (необязательно)
├── .github/
│   └── workflows/
│       └── notify-tpk.yml             ← уведомление каталога
└── ... (остальные файлы проекта)
```

## Шаг 4. Опубликовать релиз

Когда всё готово — опубликуй релиз в своём репозитории.
Именно из релизов каталог берёт файлы для скачивания.

1. Открой репозиторий на GitHub
2. В правом столбце нажми **Releases** → **Create a new release**
3. В поле **Choose a tag** введи номер версии, например `2026.9.10.1`, нажми **Create new tag**
4. Заполни **Release title** (например, `Версия 2026.9.10.1`)
5. В поле описания (**Describe this release**) — опционально — напиши, что изменилось в этой версии. Поддерживается Markdown (заголовки, списки и т.п.). Это описание появится в каталоге как **История изменений** для данной версии.
6. Прикрепи файлы продукта — нажми **Attach binaries** (см. правила именования ниже)
7. Нажми **Publish release**

Каталог обновится автоматически в течение 1–2 минут.

---

## Правила именования файлов в релизе

### Макросы (`type: macro`) и прочие инструменты (`type: other`)

Называй файлы как угодно — версия Tekla не важна. В каталог попадут **все файлы**, прикреплённые к релизу.

```
MyMacro.cs
Report_Template.xlsx
Cleanup_Tool.exe
```

### Приложения (`type: app`) и плагины (`type: plugin`)

Продукт должен иметь **отдельный файл для каждой версии Tekla**. Версия Tekla определяется автоматически по имени файла — главное, чтобы в имени присутствовало слово **Tekla** и сразу после него **год** (4 цифры).

**Вариант А — отдельный файл:**
```
MyPlugin_Tekla2020.dll
MyPlugin_Tekla2024.dll
```

**Вариант Б — архив** (когда нужно передать несколько файлов для одной версии Tekla):
```
MyPlugin_Tekla2020.zip
MyPlugin_Tekla2024.zip
```

Если в релизе есть и архив, и отдельный файл для одной и той же версии Tekla — каталог возьмёт **архив** (архив имеет приоритет).

Поддерживаемые форматы архивов: `.zip`, `.7z`, `.rar`, `.gz`, `.tar`

> **Важно для приложений:** если ни для одной версии Tekla не найдено подходящего файла, релиз будет пропущен и в каталог не попадёт.

На сайте появится переключатель версий Tekla:
```
[ Tekla 2020 ]  [ Tekla 2024 ]
↓ MyPlugin_Tekla2024.zip
```

## Если в одном репозитории несколько продуктов

Рекомендуется держать каждый продукт в отдельном репозитории.
Если это невозможно — не пиши Марии, она пошлёт тебя к клоду =D
